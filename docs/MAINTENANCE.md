# Maintain the distribution

## Verify and restore a published package

Check out the release tag you want to verify. The [artifact manifest](../artifact.json) identifies the package in that checkout. The [delivery record](DELIVERY.md) identifies the checks run for each release.

From the Kit checkout, run the repository checks with Git, Make, and Python 3.11 or newer.

```sh
make check
```

The check covers generated bytes and modes, skill entry paths, native plugin metadata, and restoration. For client discovery, follow the [installation verification](../INSTALL.md#verify-installation).

To rebuild the accepted release layout, choose a new directory outside the checkout. Its parent must already exist.

```sh
python3 scripts/package.py restore-release /path/to/releases/devnorm-1.11.0
```

The restored files and their modes match [the accepted release manifest](../release-artifact.json). The command prints the output path, release identity, and skill names.

## Change the distribution

Edit repository documentation in this checkout. To change a skill, generated metadata, or licensed resources, use the [source repository](https://github.com/samuelj1519/devnorm) and export an accepted release. See [Contributing](../CONTRIBUTING.md) for the release process and [repository export ownership](HASH-SCOPE.md) for the files the exporter owns.
