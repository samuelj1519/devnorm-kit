# 6.3 Staging and commits

These quick checks apply to ordinary task branches. A commit directly updating a project-designated integration target first needs [trusted full checks](../3-workflow/3.8-integration-and-completion.md).

Each final commit delivers one logically complete, explainable, reviewable goal, including its necessary implementation, tests, and documentation. Separate unrelated formatting or refactoring. Do not split inseparable behavior merely to increase the commit count.

1. Read working-tree changes and stage exact files or hunks. Exclude unrelated content, credentials, and temporary output. Check ownership of existing staged content; do not include someone else's changes incidentally. Whole-tree staging, `commit -a`, and path-based commits also require checking the actual included scope; shortcuts cannot bypass this check.
2. Read the actual staged diff and run applicable commit checks. An ordinary `git commit` records the index; edits after staging are not included automatically. Testing the working tree does not establish that the staged version was tested.
3. Compare the tested version with the intended commit. Where necessary, verify the exact staged tree in an isolated copy. Remaining working-tree changes cannot be covered by an unexplained claim that tests passed.
4. Commit within existing authorization and run normal hooks. Fix failures and retry without bypassing them with `--no-verify`. Verify the resulting content, SHA, and remaining working-tree state.

Use `git diff --cached --stat` for scope, `git diff --cached` for content, and `git diff --cached --check` for whitespace errors. These do not replace type, behavior, or security checks. Do not send sensitive diffs externally or copy them verbatim into logs.

When using Conventional Commits, use `<type>[optional scope]: <description>` and mark breaking changes under its rules. State the change directly in the subject. Explain reasons, limitations, and verification when needed. A short subject is a readability recommendation, not a universal hard character limit. Do not invent authors, signatures, co-authors, executors, or verification records.
