# 3.4 Execution environment

For direct execution, verify working directory, version, scope, and existing changes, then proceed to section 3.5. Do not dispatch work to yourself.

Before entering another agent's terminal, verify working directory, terminal, session ID, and launch batch, then acquire that terminal's input mutual-exclusion lock. Confirm input mode while holding the lock, send one short message, confirm receipt, and release only your own lock. Keep the full task in its brief and send its path. Processes launched by the same coordinator may not input concurrently either. Do not input without a lock, with uncertain identity or mode, or while another operator is present. Stop further input after a release failure.

An authorized user handles login and workspace trust. Before approval, match the terminal, session, launch batch, and request. Read the full request and change, confirm scope, take one action, then reread state. Do not send task text into an approval menu. GUI permission remains per action as agreed. Do not broaden it to a session or permanent permission.

For unconfirmed receipt or unknown outcome, query the original operation read-only. If you cannot prove it was not sent, do not paste again, append Enter, or resend under a new ID. Proceed to section 3.5 only after confirmed receipt and lock release. At the limit, report the task, request ID, exit code, last state, and lock status to the coordinator. Execution approval still requires the exact request and scope check.

## 3.4.1 Agent permission provisioning

Before dispatching work, pre-provision terminal permissions to reduce approval interruptions. Choose the configuration method by assistant type. The configuration applies locally only and is deleted when the task ends. The repository script is `bun scripts/agent-permissions/cli.ts install|guard|remove`. Templates are in `templates/agent-permissions/`.

| Assistant type | Configuration file | Launch convention |
| --- | --- | --- |
| Claude Code | Project `.claude/settings.local.json` | Broad allow-list plus a short deny list (deny takes precedence over allow) |
| cursor-agent | Project `.cursor/cli.json` | Deny list, and launch with `--force` |
| Codex | Project `.codex/` or global settings, depending on the client version | **To be verified**: check the current Codex documentation for equivalent `deny` rules and auto-execution switches |

**Up front · Long-term**: The dispatcher selects the profile before dispatching. The `verify` profile is for independent re-verification and by default allows writing reports only. The `implement` profile is for implementation tasks; it may modify the repository and run `git commit`, and still forbids `push` and dependency changes.

**Up front · Workaround**: Write the configuration file paths into `.git/info/exclude`. This keeps them out of `git status` and does not affect set-comparison checks. Removal condition: after a native client supports one-command permission delivery by task profile without extra working-tree pollution, and after repeated live checks pass, the requirements owner may approve removal of this repository's adapter scripts. The contents of the deny list remain long-term.

**In process · Long-term**: Run each command on its own. Do not join commands with `&&`, pipes, or `;`. Change directories with `git -C <path>`, `npm --prefix <path>`, or `env -C <path>`, not by chaining after `cd`. Otherwise prefix matching on the allow-list will fail.

**Key checkpoint · Long-term**: The standard deny list is applied with `deny` taking precedence. Network fetches: `curl`/`wget`. Remote login and copy: `ssh`/`scp`. Privilege escalation: `sudo`. Rewriting Git history and remotes: `push`/`reset`/`rebase`/`checkout`/`clean`/`stash`/`merge`/`tag`/`config`/`remote`. Dependency drift: `npm install`/`npm i`/`npm add`/`npm update`/`bun add`/`bun update`. Execution that bypasses the lockfile: `npx`/`npm exec`/`bunx`. Publishing and credentials: `npm publish`/`npm login`, and reading shell history or `~/.ssh`. The `implement` profile may allow `git commit`, and still forbids `--amend` and `--no-verify`.

Live check record (2026-11-17): In a temporary repository whose remote was an empty local repository, a live check with `claude-mi --permission-mode bypassPermissions` and a deny rule `Bash(git push:*)` blocked `git push ...`, `true; git push ...`, and `true && git push ...`; compound commands were split and matched segment by segment. Allowed: `bash -c "git push ..."` (the push actually succeeded) and `git -c x=1 push ...` (the prefix did not match). After adding deny rules such as `Bash(bash:*)`, `Bash(sh:*)`, and `Bash(env git:*)`, `bash -c` and `env` were blocked, but prefix matching can never be made complete. `Write(path)` rules in the template have no effect; Claude Code only recognizes `Edit(path)`, for both allow and deny.

Last line of defense: while the agent is running, lock the SSH key in Bitwarden, and unlock it only when a push is needed. Both the deny list and the push-URL sentinel can be bypassed; a push cannot succeed while the key stays locked.

**Key checkpoint · Long-term**: The deny list is the first line of defense. It only blocks common spellings and cannot by itself intercept irreversible operations. The second is a structural block: while the agent is running, set the push URL to an invalid value (`git remote set-url --push origin file:///nonexistent/push-disabled-during-agent-run`). On cleanup, restore the value from before `install`; if that value was empty, use `git config --unset remote.origin.pushurl`. To re-establish the baseline, run `remove` and then `install`; otherwise the old recorded value is reused. The third is `guard`, which afterward checks that the push URL is still the invalid value. Known limits: a bare `git push <URL> <ref>` is still blocked by the first layer, but a push that escapes the prefix and supplies an explicit URL, or a push to a remote other than origin, does not go through the push URL and is not stopped by the invalid value; rewriting `pushurl` is the same. Those cases can only be found afterward by `guard`.

**Key checkpoint · Workaround**: `install` records SHA baselines of `package.json`, existing lockfiles, and `.githooks/`, plus the initial `git status --porcelain` and the directory listing of `~/.npm/_npx`. Run `guard` periodically during the session. If the baseline changes, if the working tree has changes outside the report path, or if `_npx` has new entries, `guard` fails and the dispatcher immediately revokes permissions. **Removal condition**: after the client has a built-in equivalent guard, and live checks show it can replace this script's two checks (file baseline + status snapshot + `_npx`), the requirements owner may approve keeping only the standard text.

**Periodic · Long-term**: Templates and check programs ignore local agent directories (`.claude/`, `.cursor/`). Those directories are not counted in set differences at the repository root.

**Afterward · Long-term**: Run `remove` when the task ends. It deletes the configuration files, the `.git/devnorm-agent-permissions/` state, and the provisioned entries in the exclude block, and restores the push URL to the value from before `install`.

## Chinese writing responsibilities

Layer: up-front constraints. Rule class: long-term.

**Up front · Long-term**: Human-facing Chinese is written or finally edited by an agent strong in Chinese; the primary coding agent writes code only. Human-facing Chinese means rules, reports, commit messages, and handoff documents. By default claude-mi writes or finally edits it; when claude-mi is unavailable, claude-glm takes that role. The primary coding agent, cursor-agent, writes code only, plus short English or structured results.

**Up front · Long-term**: Writing style follows tech-doc-style-chinese (the Chinese technical-writing standard): lead with the conclusion and use short sentences; give a one-sentence explanation the first time a term appears; put English identifiers in code formatting; do not use hollow stock phrases that add no concrete meaning.

Rewrite examples stay in the Chinese source and in the Chinese-writing method (`delivery/methods/chinese-writing/`). The examples tighten sentences from commit 79b6d29 in this repository: split long sentences, drop filler, and keep the same meaning.
