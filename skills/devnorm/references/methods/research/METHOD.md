# Research

For browser, security, account, or multi-agent tools, check actual support and missing-tool handling under [host capabilities](references/host-capabilities.md).

For product/API-specific facts, consult installed official-documentation capabilities and the existing implementation first; record applicable versions. The host supplies search, account connectors, security backends, and credentials. This bundle neither copies connectors nor claims unavailable tools. State missing tools and explain substitute sources.

## Scope and inputs

Use for uncertainty about facts, interfaces, dependencies, or design that affects a decision. Define question, use case, required evidence, and stop conditions. Include project version, existing records, and observable acceptance.

## Procedure

1. Inspect current implementation, configuration, decisions, and verified conclusions first. Separate directly readable facts from questions needing external evidence and identify the remaining gap.
2. Prefer vendor docs, standards, original repositories and fixed versions, original studies, and actual interface output. Check behavior for the installed version. Record source date, applicable version, and location.
3. Extract only facts relevant to the question. Separate source facts, author judgments, and your inference. Seek limits, counterexamples, and opposing evidence for critical claims. Reposts of one source remain one source.
4. Where documents are insufficient, run a minimal reversible isolated experiment. Preserve inputs, commands, versions, exit codes, and raw output. Real models, accounts, and data require matching authorization.
5. Use existing project records for question, answer, sources, limits, unresolved items, and design impact. Save files under project conventions. Send externally only with authorization.

## Completion and stopping

Every decision-relevant question has a traceable answer or explicit unresolved condition. Distinguish inference from evidence. Return conflicting evidence or missing critical experiment conditions to requirements/design. Research does not grant approval or prove unrun behavior.

## Source and adaptation

Adapted from pinned Matt Pocock research. Keeps primary evidence, bounded questions, and reviewable output. Research may be done directly. Delegate only when total cost falls, with exact question, inputs, and boundaries. No fixed background role, parallel count, or personal record service.
