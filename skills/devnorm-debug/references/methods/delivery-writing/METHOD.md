# Work explanations and delivery writing

Use to explain implementation, report results, or write a PR. Reuse the project's format and scale detail to complexity.

1. Lead with the problem and observable resulting behavior. Add a precise before/after example when useful.
2. Explain mechanisms and choices that affect understanding, grounded in code and records. Mark unknown motivation as unknown instead of inventing author intent.
3. State the actual environment, exact inputs, results, and limits. Describe concrete affected behavior and recovery rather than vague metaphors.
4. Use a small diagram, table, or example only when it reduces reading effort. No mandatory image generation or fixed sections. Apply [Chinese writing](../chinese-writing/METHOD.md) to Chinese content.

Complete when readers can assess changes, reasons, evidence, and next actions. Explanation does not expand implementation scope or authorize PR creation, commits, or external sends.
