# Context recovery

**Run only when the prompt explicitly requests historical context recovery, a specified-session recap, or missing work-record research.** Ordinary task continuation reads current project records without searching all history.

1. Bound the project, topic, and necessary time range. Use a complete continuation record first and fill only material gaps.
2. Start with the current task, version, plan, checks, and open choices. Then consult authorized host history or shared records. Read minimal relevant excerpts; assume neither fixed client paths nor automatic agent fan-out.
3. Separate user reports, previous conclusions, and live state. Verify location, changes, and effective authorization. Old logs do not establish current-version success.
4. Update the existing record with goal, stage, exact inputs, completed work/evidence, original failures, remaining budget, blockers/decisions, next action, and owner. Keep bulk raw material out of the main context.

Stop when work can resume. Mark unavailable sources as gaps; do not invent history or broaden access. The host supplies accounts, history APIs, and services. This method does not modify memory stores.

Source: adapted from pinned pstack recall and ketchup. Keeps bounded recovery and concise state summaries without client-specific paths or default parallelism.
