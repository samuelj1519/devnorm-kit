# 3.8 Merge and completion

Before updating a project-designated integration target, verify authorization, exact candidate, target branch, inputs and check configuration. This includes merge, integration cherry-pick/rebase/squash, and direct commits or pushes to that target. Ordinary task-branch commits use quick checks, not automatic full checks. A trusted check service or merge tool confirms full applicable tests, dependency checks, security scans, and no coverage decline through `--full` or a verified equivalent. Author-edited success records and local commit quick checks are insufficient. Missing tools or unclear evidence stop merge.

Evidence reuse requires identical source, rules, dependencies, samples, environment, security data, and coverage baseline. Before consolidated checks, prepare the combined version only in an isolated directory or temporary index. Do not move the target branch or create a real merge commit. Run full checks and applicable acceptance for the exact combination, then merge. Changes, conflicts, or contamination return to section 3.5 and independent review. Direct tasks not updating an integration target need not run this step.

Commit only approved files with normal hooks and protect others' work. Correct shared history with new commits by default. Apply [section 6.6](../6-version-control/6.6-undo-and-history.md#66-undoing-changes-and-editing-history) to unshared editing, approved history replacement, and tags; ordinary commit or push authorization grants no exception. Check PRs, check statuses, and merge methods under [sections 6.4 and 6.5](../6-version-control/6.4-pushes-and-pull-requests.md#64-pushes-and-pull-requests). Installation, release, and push retain their own authorization. If merge succeeds but cleanup fails, report merged with completion blocked and notify the coordinator rather than claiming full completion. Record author-side checks passing, handover to independent re-verification, and overall completion separately. Planning a handover to independent re-verification is not completion, and does not by itself record `BLOCKED`.

Standard tasks record versions, implementer, reviewer, commands, exit codes, initial failures, reruns, unrun checks, evidence, and next owner. Record pitfalls, architecture violations, post-merge regressions, rework, review findings, regression count, and duplicate-code growth. Keep unknowns unknown. Direct tasks need only a brief result, not invented process records.

Before cleanup, confirm ownership, future consumers, and authorized scope. Preserve necessary source, counterexamples, and logs. Keep others' resources, active resources, and unique evidence.
