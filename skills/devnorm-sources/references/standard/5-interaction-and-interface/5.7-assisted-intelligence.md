# 5.7 Assisted intelligence and automation

Products with intelligent features or external services must let users know what the system can help with, which publicly stateable evidence was used, and which results remain uncertain; suggestions can be viewed, edited, ignored, or turned off; when the model or external service fails, a usable baseline flow remains. Required acceptance checks for assistant output are in [UI acceptance](5.8-ui-acceptance.md).

When assisted intelligence would perform a high-impact action or widen the original grant, it must show the object, destination, scope, and expected result; turn the suggestion into a verifiable plan of operations authorized once by the user for that same plan; the system executes within the approved scope and reads back the result. Users can inspect, correct, or retract reversible automated effects; permissions, data-sending scope, and follow-up settings have findable entries.

Products with scripts, APIs, or background automation must define a stable machine contract that shares the same business validation as the interface; when adjusting the first screen and help, account for existing callers.
