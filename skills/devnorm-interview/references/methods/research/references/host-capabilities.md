# Host-provided capabilities

When the task needs these capabilities, verify installed tools, authority, and versions. A method file does not establish a working backend.

| Capability | Boundary |
| --- | --- |
| Official documentation and research | For version-sensitive API/product facts, prefer the existing implementation and official sources; use openai-docs or equivalents only when the host provides them |
| Browser, terminal, native controls | Exercise the actual target; substitutes or other engines do not prove it. Cross-terminal input retains mutex requirements |
| Security scanning | Use an actual backend when requested or warranted by risk; fix scope, candidate, rules, and raw results. Static advice is not an executed scan |
| Issue/PR and account services | Verify objects and authority for feedback, publication, and status changes; keep local drafts when connectors are unavailable |
| Credentials and human authorization | Use supported host authorization flows without reading or displaying secrets; missing authority blocks affected actions |
| Multiple agents and model selection | Allocate by relationships, capability, and total cost. A named role is not proof it is installed or authorized for delegation/paid use |

State exact unexecuted work and recovery conditions. Do not install whole source bundles automatically or report substitute execution as the actual target.
