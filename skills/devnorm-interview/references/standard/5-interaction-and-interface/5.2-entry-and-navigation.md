# 5.2 Entries and navigation

Main navigation must use names users recognize and show the current location. Frequent tasks have visible entries; operations on a specific object live in the object's detail view; rare options unfold on demand. Shortcuts, command entries, and gestures may shorten expert paths; critical tasks must keep a discoverable plain entry, and users can see the shortcut while using it.

Where there are collections, lists, or search, show the current scope, active filters, sorting, and what the count means; an empty filtered list must offer a way back; disambiguate same-named objects by source, ownership, or location.

Prefer that going back preserves search, scroll position, selection, and unsubmitted input; a deep link into a detail view still reaches its parent; when input is stashed or preserved, state the retention scope and protect privacy. Mobile, desktop, and narrow windows may use different navigation components; how users recognize the same tasks, names, states, and results must stay consistent.
