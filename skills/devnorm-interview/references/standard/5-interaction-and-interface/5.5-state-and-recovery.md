# 5.5 State and recovery

| State | What the user needs to see |
| --- | --- |
| Waiting, loading, running | What is happening, whether other actions remain possible, whether it can be canceled; show progress when it can be computed accurately |
| No results, unsynced, partially visible | How much was found, what the scope is, and which conditions can change it |
| Success | Which result was confirmed; when applicable, a reviewable receipt, version, status page, or actions taken |
| Failure, blocked | Which step failed, what was preserved, and what the user can do now |
| Partially complete, unknown outcome | Which parts have evidence and which await checking; the original action can be queried or completed |

User submission, page loading, and background completion each have their own feedback; success is backed by the resulting state, and important results are persistently retrievable and perceivable with assistive technology. After failure, keep correct input and context that can be kept safely; when an external outcome is unknown, check the original operation first; repeated requests must be idempotent where applicable to avoid duplicate charges, publishes, or submissions.

Acknowledge the first step as early as possible; long work may be shown in phases, and when the estimate is uncertain, show the current phase; tasks that can be left and resumed provide a way back. Retry, cancel, and leaving the page each have a defined effect.
