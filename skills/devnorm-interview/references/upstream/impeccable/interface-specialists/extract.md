# Components and design tokens

Use only when this concern applies to the UI task. Extract components, color, spacing, and typography tokens from real repeated patterns with shared meaning. Preserve semantic distinctions, migrate actual callers, and remove duplicate definitions. Do not build a framework for one-off visual similarity. Verify states, themes, and consuming interfaces.

Verify actual visibility and interaction states in the target host. Static styles or DOM presence do not establish visibility. Keep the existing UI acceptance requirements and task scope.
