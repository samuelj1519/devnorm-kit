# Interface motion and states

Use only when this concern applies to the UI task. Use motion to explain feedback, relationships, and state changes. Cover normal, hover, focus, disabled, loading, error, and success. Respect reduced-motion preferences. Transitions must not block input, obscure errors, or provide the only state signal. Avoid unrelated decorative animation.

Verify actual visibility and interaction states in the target host. Static styles or DOM presence do not establish visibility. Keep the existing UI acceptance requirements and task scope.
