# 5.9 Cases and references

Cases illustrate design methods; when adopting a pattern, revalidate it with this project's users, risks, and devices.

| Case | Observable practice | Transferable principle and conditions |
| --- | --- | --- |
| Gmail web search | Starts from the regular search box; results support filtering, plus advanced options and operators | Keep common input direct and precise conditions on demand; the default search scope has exclusions, so scope and filters that affect judgment stay explicit and removable. The case is desktop; adjust for mobile windows and input |
| GOV.UK Carer's Allowance service | The 2016 case added a pre-submit check page; the current pattern returns from the summary to edit fields, preserves input, and goes back to the check page | High-impact, multi-field submissions merit an editable summary; simple, reversible tasks can act directly. Decide from risk, task length, and undo capability |
| Apple photo picker | The user selects photos in the system picker and the app receives the selected items, without full-library access | Acquire data with the selection scope the task needs; standing sync or library-wide organization has different permission needs and requires separate design |
| GitHub pull request review | Reviews collect pending comments beside exact changes, then submit an explicit decision | Drafts, local actions, and final publication each have a state; confirmation shows the scope about to become public. Whether review blocks merge depends on repository configuration |
| Stripe Checkout | Delayed payment methods may settle after checkout; fulfillment follows server-side payment status and handles repeated notifications in one session | Distinguish submitted, pending, and success when external results are asynchronous; refresh or retry must find the original result. Adopters still design from their own transaction evidence and retry rules |
| Android adaptive navigation | One set of top-level destinations switches navigation components with window size and posture | Adjust interface structure across devices while keeping familiar concepts, locations, and task capabilities; component defaults are Material 3, so use each platform's conventions |
