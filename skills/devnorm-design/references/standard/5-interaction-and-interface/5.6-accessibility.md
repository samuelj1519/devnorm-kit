# 5.6 Accessibility and device adaptation

Web projects should target WCAG 2.2 AA for design and acceptance, combined with the applicable project rules; native products are accepted against the target platform's assistive technology and system settings. Both must provide a complete accessible path for critical operations.

Accept semantic names and roles, focus order, focus visibility, keyboard exit, contrast, text resizing, and status announcements. WCAG 2.2 AA requires that the focused component not be fully obscured by author content and that applicable status changes be perceivable with assistive technology; on critical paths, prefer keeping the focused component fully visible. Touch and drag operations provide applicable target sizes and alternatives; audio, video, and identity verification follow their applicable requirements.

Support users' input methods and system preferences. Check critical tasks under narrow screens, configuration changes, long text, enlarged type, and reduced motion, covering focus across page changes, dialog returns, and errors. Combine automated checks with real user-task testing: walk the full path with the keyboard and the applicable assistive technology, then record actual problems and uncovered areas.
