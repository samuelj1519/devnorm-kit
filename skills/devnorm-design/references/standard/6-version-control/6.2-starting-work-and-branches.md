# 6.2 Starting work and branches

1. Verify the actual repository, current branch, HEAD, target branch, and existing changes. Confirm ownership of each change and resource. A branch name, commit author, or absence of a visible remote ref does not establish ownership by itself.
2. Select the working location and fix the comparison base. Do not automatically stash, reset, clean, or switch branches in a directory with unknown changes. Preserve the state and resolve ownership or location conflicts first.
3. Use a short descriptive branch name and keep unrelated goals separate. Parallel changes normally use one branch per task, with a designated integrator for the shared target. Only one writer owns a working directory or branch at a time.

Git worktrees have separate working directories, HEADs, and indexes, but normally share refs, objects, and configuration. They do not isolate real application data, billing, or all Git state. Physically isolate source, test data, and build outputs under section 2.3. Do not operate a branch owned by another working directory from a different one, or change shared configuration without authorization.
