## Git closeout

<!-- devnorm:condition:git-delivery:start -->
Use the project or task's agreed delivery target on both routes.

1. After applicable checks pass, [commit each complete, independently verifiable increment and confirm its SHA](../6-version-control/6.3-staging-and-commits.md) within existing authorization. A single small task can use one commit after final acceptance. At closeout, the coordinator confirms that any remaining verified changes are committed within scope.
2. For required remote delivery, the authorized coordinator verifies the repository, effective push destination, target ref, outgoing commits and [push authorization](../6-version-control/6.4-pushes-and-pull-requests.md#push-authorization). Use the project's merge method. For direct delivery to the target branch, obtain [trusted full checks](integration.md) on the exact combination with the current target before integrating and pushing. Recheck the combination if the target or tested content changes. Read back the target SHA from the same push destination. For local-only delivery, verify the local result.
3. Use the project release policy and delivery needs to decide whether the batch requires a separate version for installation, deployment, upgrade, reference, or rollback. Changes that can ship with the next version can follow routine delivery. When release is due, verify the exact release commit and applicable artifacts, then create the version tag within release authorization and confirm its target. If tag publication is authorized, push it and verify the remote tag and its target. Check separate authorization for a release page, installation or deployment.

Before reporting completion, confirm the applicable local commit SHAs, remote branch SHA and version tag. If a required step lacks checks, permission or evidence, report the completed steps and the specific blocker. Continue independently authorized work.
<!-- devnorm:condition:git-delivery:end -->
