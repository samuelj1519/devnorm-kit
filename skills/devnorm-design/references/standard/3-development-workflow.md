# 3. Development workflow

Handle simple low-risk tasks directly. Use the seven-step standard workflow for other work. Complete full checks before an actual merge. See the [overview](3-workflow-overview.md) and complete [project setup](2-project-setup.md) for a new project.

The standard workflow follows sections 3.2 through 3.8. Agree on waiting and rework counts or time limits in the task brief before execution. At a limit, preserve progress, notify the coordinator, stop, and report `BLOCKED`. Send approval decisions to the requirements owner. On resumption, recheck versions, inputs, and permissions, then return to the original step without expanding authority. Direct tasks do not require a retroactive task brief.
