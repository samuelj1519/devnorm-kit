# Experience and visual review

Fix the page, component, version, and user task. Complete the main flow with the same content, then assess support for that task rather than personal taste.

1. Read current design direction, project vocabulary, audience constraints, and allowed changes.
2. Check primary action, reading order, findability, timely feedback, and recoverable failure.
3. Check typography, density, line length, grouping, spacing, color roles, repeated visuals, and control consistency against real content and product-specific behavior.
4. Validate visual judgments in actual rendering, separately from static code or detector output. Independent contexts may help only when justified by total cost and authorization. Do not prescribe headcount or models.
5. Present the strongest evidenced issues, effects, and actionable repairs. Separate approved design choices from choices requiring the owner.

Keep reporting focused on the user task and project records. Missing access or rendering limits scope and keeps unverified items unrun. Review does not expand change authority.
