# 中文技术写作

<!-- 原作者 Fenng（GitHub @Fenng）；DevNorm 基于固定 chinese-style fork 改编，并纳入用户已批准的自然中文与术语规则。 -->

## 适用与输入

用于中文技术文档、产品文案、界面文案、API 说明、操作手册和故障排查的撰写、改写、校对或审阅。先确认模式、受众、载体、事实来源及目标项目约定。

## 不可改动的内容

事实、逻辑、条件、例外、风险和法律含义优先。代码字面量、JSON 键、URL、API 路径、数据库字段、命令、配置项、错误原文及用户指定的固定文本保持准确。未经来源支持不新增日期、数字、时限、SLA、能力或因果结论，不把「可能」「计划」「建议」改为确定事实。

## 按任务操作

1. 读取目标项目的有效规则、术语表和已有文档；示例约定只作参考。撰写先确定事实与结构，改写保留原意及层级，校对只处理约定范围，审阅先列问题及原文位置。
2. 标记机器可读内容、引用、数字及限制，确定保护范围。缺少会改变结论的信息时标记待确认，继续组织已有依据。
3. 先修复语义、指代、否定范围、逻辑顺序和遗漏。段落保持单一主题，句子有明确主干；条件和风险放在动作之前，职责写明实际执行者。
4. 使用自然的简体中文和行业通行术语。将生硬直译、含义不明的比喻、自造术语和未解释的内部缩写改成明确对象、动作或技术概念。准确的「缓存」「事务」「快照」「网关」等术语按原义保留，官方名称和机器标识保持原样。
5. 按任务读取资料：处理术语、直译、比喻和排版时读[术语与排版](references/terminology-and-typography.md)；处理 API 状态时读[状态与错误文案](../../upstream/chinese-style/chinese-writing/references/api-status-copy.md)；处理操作、故障排查或安全步骤时读[受控中文技术写作](../../upstream/chinese-style/chinese-writing/references/controlled-technical-chinese.md)；建立项目规则时参考[覆盖模板](../../upstream/chinese-style/chinese-writing/references/project-overrides-example.md)。
6. 再调整标题、段落、列表、语气和排版。标题与表头反映主题或用途；可见正文中中文与英文、数字和行内代码之间留一个半角空格。中文段落保持一段一行，代码、表格、HTML 和固定引用保留原有结构。
7. 对照原文检查事实、单位、条件、例外、主语、因果与确定程度。批量修改先保护 Markdown 和机器内容，先验样本再扩展；检查固定名称、命令、链接目标和周边正文。自动警告辅助判断，不能证明表达一定正确。

## 完成与停止

默认改写交付完整稿；重要语义取舍和待确认项另列。检查自然中文、术语一致、可执行性和事实保真，确认代码、命令及引用没有被排版替换破坏。事实冲突或必须修改固定文本时交回明确选择，不自行补造信息。
