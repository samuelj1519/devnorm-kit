# Writing for agents

## Scope and inputs

Use for skills, AGENTS.md, execution guides, and other agent-readable material. Establish real requests, existing reader context, target file, discovery conditions, and authorization.

## Procedure

1. Test the trigger against real requests. State what the entry handles and when to use it. Describe exclusions only to prevent likely false triggers. Keep normal discovery unless the user requests manual-only invocation.
2. Separate decisions every task needs from branch-specific material. Keep purpose, critical constraints, and routing in the entry. Put conditional steps, examples, and reference behind explicit pointers. One capability does not need another router.
3. Write actions in execution order with observable completion criteria. Put conditions and risks first. Identify object, input, result, and failure return. Use explicit limits for important boundaries.
4. Reference authoritative configuration and actual commands rather than duplicating volatile facts. Explain when to read a file and use an existing relative path. Keep runtime resources and licenses in standalone exports.
5. Remove instructions that do not affect behavior, duplicates, and obsolete content. Retain evidenced non-obvious constraints, stop conditions, and user choices. Do not generalize one task detail into a universal rule.
6. Test representative requests for discovery, applicable reading, required steps, and correct stopping. Verify risky methods in an independent context with isolated samples where useful. Delegation and paid models retain task authorization and cost limits.

## Completion and stopping

Triggers, steps, material, and completion criteria agree. New scripts have run and references work independently. Format checks prove format, not behavior. Record factual gaps, stop unauthorized actions, and preserve current content and proposals.
