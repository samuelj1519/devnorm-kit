# Responsive and input adaptation

Use only when this concern applies to the UI task. Adapt layout to target viewport, content priority, and input method rather than scaling proportionally. Check narrow content, touch targets, keyboard focus, overflow, and text zoom. Reuse existing breakpoints/components. Consult actual native-platform requirements separately; web checks do not establish native acceptance.

Verify actual visibility and interaction states in the target host. Static styles or DOM presence do not establish visibility. Keep the existing UI acceptance requirements and task scope.
