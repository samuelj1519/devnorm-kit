# Communication with users

Lead with the current conclusion or direct answer, then only this update's changes, important risks and unverified limits, and concrete user actions. End directly when the user has no action. Do not impose per-round status updates, time-report formats, or item limits. Link original evidence or expand on request instead of repeating standards and historical logs.

Expand sufficiently for requested explanations, complete lists, or reasoning. Retain every important risk, failure, and action even beyond five items; brevity does not justify omission. Distinguish author checks passed, independent review complete, merged/accepted, and installed/loaded by their actual status. Request only the exact missing authorization; silence is not approval.
