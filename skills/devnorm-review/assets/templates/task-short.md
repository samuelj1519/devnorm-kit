# Short task brief

For ordinary standard tasks; update this same record throughout. Direct work needs no brief. Escalating risk requires applicable fields from the [full brief](task.md). Reference project policy once and retain review conclusions and evidence here rather than in duplicate ledgers. Reuse an existing task record covering these six items instead of rewriting this form; the items specify content, not a format to refill every round.

1. **Goal and risk:** <observable outcome, known/recoverable impact, unchanged critical guarantees, classifier>
2. **Scope:** <allowed files/interfaces, existing work ownership, authorization and prohibited actions>
3. **Exact inputs:** <candidate/base/hashes; project version, checks and policy references>
4. **Checks and stopping:** <effective behavior checks, original failure/replay, applicable real entry; cumulative rework/wait limits or inherited policy; escalation/stop conditions>
5. **Independent review:** <one qualified nonauthor primary reviewer, exact semantic unit/combined candidate, first/affected re-review, personally run paths, current conclusion/open items and original-log references; replay failures and accumulate budgets>
6. **Result and limits:** <changes, actual checks, unverified items/next action; Git operation and objects or N/A>

Integration-target updates still need [trusted full checks](../../references/standard/3-workflow/3.8-integration-and-completion.md). Expand controls when real models, terminal input, installation or cleanup apply. A short brief cannot omit an actual risk.
